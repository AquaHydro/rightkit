# 性能复测

先运行 `make verify`，再运行 `scripts/perf/run.sh`。脚本使用测试构建的 `RightKitCore`，在系统临时目录创建并清理自己的数据，不启动应用，也不读取用户设置。

- 菜单基准：30 个临时目录，0 / 100 / 1000 个模拟选中项；每种配置运行 50 次，分别输出菜单规则与图标查询的 p50/p95。它不包含 Finder 回调、实际选中项元数据读取或 Finder 绘制成本，不可作为真实右键延迟。
- 传输基准：一个目录内 10000 个 1 KB 文件，运行三轮；分开记录预扫描和复制。它只代表本机同卷临时目录，不代表外接盘或云盘。

菜单规则合成基线（优化前，同一构建方式）：100 项、工具箱开启的 p50/p95 为 5/6 ms；1000 项为 38/39 ms。复测后分别为 3/3 ms 和 10/11 ms。图标查询在 1000 项下约 1 ms。关闭工具箱时 1000 项为约 8–10 ms，说明主要耗时来自原先重复的选中项分类。

传输基线：10000 项预扫描 25–28 ms，复制 801–859 ms。预扫描在这个负载中不是主要耗时，因此没有改变扫描策略。

## 完整菜单构建专项

运行 `python3 scripts/perf/run_menu.py`。它单独编译 Release 的 RightKitCore 和扩展使用的 MenuRenderer/PendingPasteState，不依赖旧的 Debug 产物，不启动或注册扩展、不读取已安装应用的设置。

负载包括真实临时文件的元数据、30 个目标目录、10000 条待粘贴记录、AppKit NSMenu/NSMenuItem 和完整图标绘制，以及 1/10/30 个监视目录和 100/1000/10000 个模拟选择的规则匹配。每组输出首样本及 p50/p95。presentation-cold 表示新建呈现器（不等同于扩展进程冷启动）；pipeline 的首样本也不包含 Finder 和系统加载扩展的等待。p95 使用 nearest-rank，缓存暖机样本仍计入统计。

基准中的应用列表为空，不代表包含大量打开工具的配置；文件仅为本地临时文件，不代表网络卷、云盘或外接盘。前后结果及证据边界见 [2026-09-26 测量记录](../../docs/performance/2026-09-26-menu.md)。
