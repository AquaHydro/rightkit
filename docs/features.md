# 功能规格

本文描述 RightKit 要实现的产品行为。编号稳定，不要复用。界面形态见 [设计规范](../DESIGN.md)，工程边界见 [工程边界](technical.md)，验收见 [验收](verification.md)。

RightKit 有官网版和商店版两个发布渠道，功能相同，差异只有 `F-082` 列出的几项。两个渠道都运行在 App Sandbox 里，所以访问文件前需要用户授权文件夹（`F-080`）。

不实现 `F-003` 和 `F-052`。没有表面材质开关，也不为 macOS 26 以前的系统写回退；也不通过未公开的 Finder 偏好设置控制隐藏文件显示。

| --- | --- |
| 主题 | 跟随系统 |
| 语言 | 跟随系统 |

| 显示菜单栏图标 | 开 |
| 在菜单项中显示图标 | 开 |
| 监视目录 | 空，欢迎窗口里授权的文件夹（`F-080`） |
| 新建、剪切粘贴、复制移动、常用目录、在应用中打开 | 全部开 |
| 彻底删除前二次确认 | 开 |
| 新建类型 | `txt`、`md`、`rtf`、`docx`、`xlsx`、`pptx` 开，其余关 |

## 设置

设置窗口的分栏和组件按设计规范。某一功能组关闭时，这一页里它的子项禁用但不隐藏；访达菜单里则整个不出现。

### 通用

`F-001` 访达扩展有四种状态，按下面顺序判断，取第一个成立的：

- 未启用：系统报告扩展关闭。动作是「打开系统设置」。说明文字是「在“系统设置 → 通用 → 登录项与扩展”中打开 RightKit 的访达扩展，右键菜单才会出现。」
- 后台服务已关闭：扩展已打开，但用户在「允许在后台」里关掉了 RightKit，菜单命令无法送达主程序。动作是「打开系统设置」，落到登录项页面。说明文字是「请在“系统设置 → 通用 → 登录项与扩展 → 允许在后台”中打开 RightKit。」
- 未运行：系统报告扩展打开，但没有本次登录的心跳。动作是「重启访达」。说明文字是「重启一次访达，菜单就会出现。」
- 已启用：系统报告扩展打开，且扩展在本次登录中写入过心跳。动作是「重启访达」。说明文字是「一切就绪，去访达里右键试试。」

扩展发现后台服务不可用时，直接打开主程序，主程序打开设置的「通用」页显示这个状态。

状态卡片上的 Riko 表情只是辅助，状态文字和说明文字必须同时显示。

打开系统设置必须落到「系统设置 → 通用 → 登录项与扩展」里的访达扩展页面。

重启访达前要确认。标题「重新启动访达？」，正文「访达会短暂关闭并重新打开。」按钮「重新启动」和「取消」。确认后请访达正常退出，退出后由 RightKit 重新打开访达。第一次重启时系统会询问是否允许 RightKit 控制访达。用户拒绝或访达没有退出时，提示「无法重新启动访达。」正文「请在“系统设置 → 隐私与安全性 → 自动化”中允许 RightKit 控制访达，或按住 Option 键右键点按程序坞中的访达，选择“重新开启”。」按钮「好」。

`F-002` 主题：跟随系统、浅色、深色。只影响 RightKit 自己的窗口。

`F-004` 语言：跟随系统、English、简体中文。内置模板名和内置界面文案跟随这个选择。用户自己写的模板名、文件夹名不翻译。

`F-005` 登录时启动、显示菜单栏图标、在菜单项中显示图标。三个开关互相独立。

登录时启动必须由用户明确打开，RightKit 不自动开启。首次启动时默认关闭，欢迎窗口里的开关初始也是关。关闭时访达菜单照常可用：点击命令时，主程序没运行就会被启动。

菜单栏菜单在图标打开时出现，内容按设计规范：扩展状态（不可点）、五个功能组开关、`设置…`（⌘,）、`退出 RightKit`（⌘Q）。功能组开关和设置页是同一组值。任何功能都不能只能从菜单栏进入。

首次启动显示一次欢迎窗口，布局按设计规范。「开始使用」打开设置并记下已显示；「稍后设置」只记下已显示。窗口里的登录时启动和菜单栏开关写入 `F-005`，文件夹授权按 `F-080`。

欢迎窗口同时显示 `F-001` 的扩展状态卡片，状态、说明文字和「打开系统设置」都与 `F-001` 相同，随系统变化自动刷新。欢迎窗口不提供重启访达，这个动作留在设置的「通用」页。

`F-006` 五个功能组可以各自开关：新建、剪切粘贴、复制移动、常用目录、在应用中打开。

`F-007` 彻底删除前二次确认。关闭后，普通项目不再弹确认。受保护位置的拒绝提示不受这个开关影响。

`F-008` 访达工具栏菜单始终只放「设置…」。它不读取当前文件夹或选择，也不提供文件操作。

`F-009` 用户可以管理监视目录。首次启动时没有监视目录，用户在欢迎窗口或设置里授权后才有（`F-080`）。用户可以添加或移除目录，每次添加都通过系统的文件夹选择面板，同时完成授权。目录不存在时设置行显示「该文件夹已不存在。」，不注册给 Finder 扩展。不能添加文件系统根目录 `/`、系统目录或用户主目录以外的其祖先目录。监视目录及其子目录才显示 RightKit 的上下文菜单。

### 新建

`F-010` 内置类型、菜单名和模板内容：

| 扩展名 | 简体中文 | English | 模板内容 |
| --- | --- | --- | --- |
| `txt` | 文本文档 | Plain Text | 空文件 |
| `md` | Markdown | Markdown | 空文件 |
| `rtf` | RTF 文稿 | Rich Text | 最小合法 RTF：`{\rtf1\ansi\pard\par}` |
| `docx` | Word 文档 | Word Document | 最小合法 Word 文件 |
| `xlsx` | Excel 工作簿 | Excel Workbook | 最小合法 Excel 文件 |
| `pptx` | PowerPoint 演示文稿 | PowerPoint Presentation | 最小合法 PowerPoint 文件 |
| `json` | JSON | JSON | `{}\n` |
| `xml` | XML | XML | XML 声明加空的 `<root>` |
| `html` | HTML | HTML | 带 `utf-8` 的最小 HTML 文档 |
| `css` | CSS | CSS | 空文件 |
| `js` | JavaScript | JavaScript | 空文件 |
| `sh` | Shell 脚本 | Shell Script | `#!/bin/zsh\n` |

文本模板使用 UTF-8。三个 Office 模板必须能被对应应用打开且不要求修复。默认顺序就是上表顺序。

`F-011` 每个类型可以单独开关。关闭的类型不出现在菜单里。

`F-012` 「创建后自动打开文件」。打开使用该文件类型的默认应用，不是「在应用中打开」列表。文件已经创建成功但打开失败时，保留文件并提示「无法打开文件。」

`F-013` 「创建前询问文件名」。打开时，菜单项带省略号。对话框正文「输入新文件的名称：」，默认文字「未命名」（英文界面为 `Untitled`），按钮「创建」和「取消」。用户取消则不创建。名称去掉首尾空白后如果为空，保持对话框。若名称还没有以该类型的扩展名结尾，自动补上；已有则不重复补。

`F-014` 用户可以把任意文件添加为自定义模板。应用保存一份副本，而不是继续引用原文件。用户要为它写菜单名，默认用原文件名。复制在后台进行，导入期间设置窗口保持可用，并提供取消；同一时间只执行一次导入。只有副本完整保存后才加入设置，取消或失败时清理未完成的副本。创建时整份克隆这副本。副本丢失或不可读时提示「无法创建文件。」导入失败提示「无法导入模板。」自定义模板可以单独开关和移除。

`F-015` 内置类型和自定义模板在同一个列表里拖动排序，顺序原样出现在菜单里。

`F-016` 「恢复默认」把内置类型的开关和顺序、以及 `F-012`、`F-013` 恢复成默认值。自定义模板保留。

创建规则：

- 没有选中项目时，创建在当前文件夹。只选中一个文件夹时，创建在该文件夹里。
- 不询问文件名时，文件名是「未命名」加扩展名。英文界面用 `Untitled`。
- 目标已有同名项目时，在扩展名前加 ` 2`、` 3`，直到可用。不覆盖。
- 先写同目录临时文件，再改成最终名字。失败时删掉临时文件并提示「无法创建文件。」
- 只读目录、名称非法、磁盘不足都走这句失败提示，不创建半截文件。

### 在应用中打开

`F-020` 每一行保存应用的 bundle ID、显示名、角色和是否开启。角色是「编辑器」或「终端」。

内置检测对象：

| 应用 | bundle ID | 角色 |
| --- | --- | --- |
| 终端 | `com.apple.Terminal` | 终端 |
| Ghostty | `com.mitchellh.ghostty` | 终端 |
| Visual Studio Code | `com.microsoft.VSCode` | 编辑器 |
| Xcode | `com.apple.dt.Xcode` | 编辑器 |

`F-021` 「添加应用…」让用户选择一个 `.app`。新应用默认是编辑器，并默认开启。同一 bundle ID 不重复添加。

`F-022` 「检测已安装工具」只查找上表四个应用。新发现的加入列表并开启。已经在列表里的不改角色、不改开关。

`F-023` 终端打开目录，编辑器打开项目本身：

- 没有选中项目：两类应用都打开当前文件夹。
- 选中文件夹：打开这些文件夹。
- 选中文件：编辑器打开这些文件；终端改为打开这些文件所在的目录，并去重。
- 应用已卸载：这一行显示「“名称”已不在系统中。」，菜单里不列出。启动时才发现丢失，提示同一句。
- 启动失败提示「无法用“名称”打开。」
- 不用字符串拼接 shell 命令。路径里的空格、引号和换行必须安全。

### 常用目录与发送到

两套列表独立。常用目录只负责在访达中打开文件夹。发送到只负责作为「复制到」和「移动到」的目标。

`F-030` 常用目录可以添加、开关、移除。菜单名使用该文件夹在访达中的显示名。点击后在访达中打开它。文件夹已不存在时，设置行显示「该文件夹已不存在。」，菜单里不列出。

`F-031` 发送到的添加、开关、移除和失效提示与常用目录相同。说明文字：「这些文件夹是「复制到」和「移动到」的目标。」

`F-032` 「复制到」和「移动到」的子菜单列出已开启且仍然存在的发送到目录，最后一项始终是「选择文件夹…」。选择文件夹使用系统的目录选择面板，然后执行同一次复制或移动。

复制和移动：

- 复制后源项目仍在。移动后源项目不在；跨卷时先复制再删除源。
- 目标已有同名项目时自动编号，不覆盖。
- 不能把文件夹移动到它自己里面。这种项计为失败。
- 符号链接只处理链接本身，不处理链接指向的内容。
- 多项里有的成功、有的失败：保留成功项，只弹一条「部分项目无法传输。」
- 全部失败：提示「无法复制项目。」或「无法移动项目。」

`F-033` 剪切把所选项目记入应用自己的待粘贴列表，不占用系统剪贴板。没有待粘贴项目时不显示「粘贴」。

粘贴的目标是当前文件夹；若只选中一个文件夹，目标是该文件夹。粘贴执行移动：已成功移动的项目从待粘贴列表移除；失败的项目和取消后尚未处理的项目保留，可以再次粘贴。全部成功后列表清空，不再出现粘贴。源已不存在的项失败，仍保留在列表中，直到下一次剪切替换列表。

`F-034` 是 `F-032` 的菜单入口，规则不另写一套。

### 工具箱

`F-040` 每个命令可以开关和拖动排序。「恢复默认」把 16 个命令全部打开，并恢复下面的顺序。关闭的命令在所有入口隐藏。没有可用命令时不显示「工具箱」。

默认顺序和分组：

1. 拷贝路径、拷贝名称
2. 根据文件名新建文件夹、发送替身到桌面、隔空投送、授予写入权限、文件信息（哈希）…
3. 隐藏或显示所选、隐藏或显示扩展名
4. 转换图片…、生成 macOS 图标集、生成 iOS 图标集、设为壁纸、设置文件夹图标…
5. 解散文件夹、彻底删除…

需要继续输入或确认的项目才带省略号。确认开关关闭时，「彻底删除」不带省略号。

设置里按上面五组分节，命令只能在自己的分组内拖动排序，组的先后固定。访达菜单按同样的分组和组内顺序显示，组与组之间加分隔线，「解散文件夹」和「彻底删除」因此始终在最后一组。旧版本存下的跨组顺序照常读取，用户下一次拖动时按分组重排。

## 工具行为

`F-043` 在文件旁边新建文件夹，文件夹名是去掉最后一个扩展名后的文件名。没有扩展名时用完整文件名。然后把文件移入。先用临时文件夹名创建，避免和源文件同名冲突。目标名被占用时自动编号，不覆盖。

`F-044` 在桌面创建替身。重名时自动编号。失败提示「无法创建替身。」

`F-045` 调用系统隔空投送。这台 Mac 不支持时提示「这台 Mac 无法使用隔空投送。」

`F-046` 切换选中项的隐藏标记。失败提示「无法更改可见性。」

`F-047` 切换文件扩展名的显示。失败提示「无法更改扩展名显示状态。」

`F-048` 给选中项本身加上当前用户的写入权限，不递归，不改变所有者。失败提示「无法授予写入权限。」

`F-049` 对普通文件计算 MD5、SHA-1、SHA-256、SHA-512，顺序固定。窗口按设计规范。计算在主程序后台流式进行，可以取消。空文件是合法输入。目录不出现此命令；若请求仍然到达，提示「仅支持为文件计算哈希。」读失败提示「无法读取文件。」文件在读取中变化时，放弃这次结果并使用同一句失败提示。

`F-050` 把文件夹里的直接子项移到它的父目录，再把变空的文件夹放进废纸篓。不永久删除子项。包和应用程序不当作可解散的文件夹。子项重名时自动编号，不覆盖。某个文件夹无法完成时，保留已移动的子项，并提示「无法解散文件夹。」受 `F-073` 保护的文件夹不解散。

`F-051` 永久删除，不经过废纸篓。确认开关打开时，标题是「彻底删除“名称”？」或「彻底删除 N 个项目？」，正文「此操作无法撤销。」按钮「彻底删除」和「取消」，没有默认按钮，Esc 取消。

`F-052` 不实现。RightKit 不修改 Finder 的全局隐藏文件显示偏好，也不因这项能力重启 Finder。

`F-053` 先选择输出格式：PNG、JPEG、HEIC、TIFF。选择用一个对话框：标题「转换“名称”」，多张时「转换 N 张图片」；附带分段选择器，默认上次的选择，首次为 PNG；按钮「转换」和「取消」。JPEG 和 HEIC 不保留透明通道，透明处铺白。输出写在源文件旁边，扩展名换成目标格式，重名自动编号，不覆盖。不可读时提示「“名称”不是可读取的图片。」转换失败提示「无法转换“名称”」。

`F-054` 在源文件旁边生成同名 `.iconset` 和 `.icns`。图标集包含 16、32、128、256、512 点，以及各自的 @2x。源图不是正方形时，居中裁成正方形再缩放。`iconutil` 失败提示「iconutil 生成 ICNS 文件失败。」

`F-055` 在源文件旁边生成名为「文件名 iOS」的文件夹（去掉扩展名，重名自动编号），内含这些像素尺寸的 PNG，文件名为 `icon-尺寸.png`：1024、180、167、152、120、87、80、76、60、58、40、29、20。裁切规则与 `F-054` 相同。

`F-056` 把这一张图片设为主显示器壁纸。失败提示「无法设置壁纸。」

`F-057` 一个文件夹加一张图片时直接设置。只有文件夹时让用户选图片；只有图片时让用户选文件夹。失败提示「无法设置文件夹图标。」

批量操作中部分成功、部分失败时，只弹一条汇总。复制和移动用「部分项目无法传输。」删除用「部分项目无法删除。」其他用「部分项目无法完成。」全部失败时用该命令自己的失败句。不要每个文件各弹一个窗口。

## 删除保护

`F-073` 先解析符号链接，再判断目标本身：

- 等于文件系统根目录 `/` 或当前用户的主目录：拒绝。
- 位于 `/System`、`/usr`、`/bin`、`/sbin`、`/Library`、`/private/var` 之内，含这些目录本身：拒绝。

用户主目录里面的普通项目可以删除。`/Applications` 不在保护范围内。

选择里只要有一个受保护项目，就整批不删除。标题「受保护的位置」，正文「系统目录与个人主目录无法通过 RightKit 删除。」按钮「好」。这是告知，不能继续。

## 进度

`F-075` 复制到、移动到、粘贴、解散文件夹、批量转换图片、生成两种图标集在执行超过 1 秒时显示进度窗口。窗口没有父窗口，尺寸由内容决定，内容是「正在复制…」这类进行中文案、进度条、当前文件名（等宽）和「取消」按钮。结束后自动关闭。同时进行的多个操作各有一个窗口。

取消时已完成的项目保留，不回滚；当前项写了一半的目标或临时文件被清理，源不变。跨卷移动在复制阶段取消时源仍在。取消不弹失败汇总。

## 二维码、翻译和快捷指令

`F-070` 二维码在本机生成，不上传文本。系统服务和快捷指令都打开同一个窗口。窗口有文本框、预览、`拷贝图片` 和 `存储为 PNG…`。文本为空时两个动作禁用。支持 Unicode。生成或保存失败提示「无法保存二维码。」

`F-071` 提供「使用 Google 翻译」和「使用百度翻译」两个系统服务。按应用语言把文本放进对应网站的网址并打开浏览器：中文界面目标语言为中文，英文界面目标语言为英文，源语言自动检测。文本必须做百分号编码。不修改用户的文件和剪贴板。网址超过 8000 个字符时提示「文本过长，无法打开翻译页面。」打不开时提示「无法打开翻译页面。」

`F-074` 对聚焦和快捷指令暴露这些动作：拷贝路径、拷贝名称、新建文件、文件哈希、转换图片、生成 macOS 图标集、生成 iOS 图标集、生成二维码、在应用中打开。彻底删除和解散文件夹不做。新建文件没有指定目录时，创建在桌面。转换图片的快捷指令用格式参数，默认 PNG，不再另弹格式对话框。

## 文件夹授权

`F-080` RightKit 只能访问用户通过系统文件夹选择面板授权过的文件夹，以及其中的全部内容。监视目录、常用目录和发送到列表都经过这个面板，添加即保存授权，重启后依然有效。「复制到」「移动到」和设置文件夹图标中的临时选择只供当前操作使用，不保存长期授权，不加入监视目录或其他列表；后续操作需要重新选择，或先将目录加入设置列表。「当前用户主目录」指真正的 `/Users/名称`，不是应用的沙盒容器。

- 欢迎窗口里有一行授权：标题「授权访问个人文件夹」，说明「RightKit 只能在你授权的文件夹里新建、复制和整理文件。建议授权个人主文件夹。」按钮「授权…」。点击后打开文件夹选择面板，初始位置是当前用户主目录，按钮「授权」。选中的文件夹加入监视目录，受 `F-009` 的限制；不符合时提示 `F-009` 的「无法监视这个文件夹」。授权成功后这一行显示文件夹名和「已授权」，按钮换成「更改…」，重新选择的文件夹替换刚才授权的那一个。自动补上的默认常用目录和发送到跟着更新：不在新文件夹内的去掉，新文件夹内的补上。
- 跳过授权时没有监视目录，访达菜单不出现，「通用」页显示 `F-009` 的空状态。
- 授权失效（文件夹被移到别的卷、权限被系统撤销等）时，包括因无权访问而无法确认目录是否存在，设置里这一行显示「需要重新授权。」并提供「重新授权…」，访达里不再注册这个目录。
- 命令要读写的项目不在任何已授权文件夹内时（例如「发送替身到桌面」而桌面没有授权），不执行，提示「RightKit 无权访问“名称”。」正文「请在设置里把它所在的文件夹加入监视目录；如果那个文件夹显示「需要重新授权。」，点「重新授权…」。」按钮「好」。
- 快捷指令传入的文件本身可以读取。输出写在源文件旁边的动作，源文件所在文件夹也必须已授权，否则按上一条提示失败。

## 检查更新

`F-081` 只有官网版有检查更新，商店版由 App Store 负责更新。

- 「通用」页的启动与菜单栏分组里有开关「自动检查更新」，默认开。打开时，主程序启动后若距上次检查超过 24 小时，就在后台检查一次。
- 关于弹出层有「检查更新…」按钮，随时手动检查。
- 检查读取 GitHub 仓库 `AquaHydro/rightkit` 最新的正式 Release（不含草稿和预发布），把去掉 `v` 前缀的标签与当前 `CFBundleShortVersionString` 按语义化版本比较。
- 有新版本时提示：标题「RightKit X.Y.Z 可用」，正文「你正在使用 A.B.C。前往下载页面获取新版本。」其中 X.Y.Z 是新版本号，A.B.C 是当前版本号。按钮「前往下载」和「稍后」。「前往下载」在浏览器中打开这个 Release 的网页，RightKit 自己不下载也不安装任何文件。
- 手动检查时已是最新：「RightKit 已是最新版本。」检查失败：「无法检查更新。」自动检查的这两种结果都不提示。
- 同一个新版本在自动检查中被点过「稍后」，之后的自动检查不再提示它；手动检查照常提示。

## 发布渠道

`F-082` 官网版和商店版行为相同，只有下面几项不同：

| 项目 | 官网版 | 商店版 |
| --- | --- | --- |
| 获取方式 | 官网跳转 GitHub Release 下载 DMG，免费 | Mac App Store，付费 |
| 更新 | `F-081` 检查更新并跳转下载页 | App Store 更新，没有 `F-081` 的开关、按钮和网络请求 |
| 关于弹出层 | GitHub 和「反馈问题」两个链接，外加「检查更新…」 | 只有「反馈问题」，打开邮件 `contact@yiliang.me`（仓库私有期间）；不提供 Release 下载入口或检查更新 |

两个版本的 bundle ID 和设置各自独立，可以同时安装。同时安装且都打开访达扩展时，访达菜单会出现两份，这是预期行为，不做互相检测。

## 文案

简体中文是第一语言，English 同步维护。访达、隔空投送、替身、拷贝、废纸篓使用系统译名。剪贴板用「拷贝」，文件传输用「复制」和「移动」。按钮和菜单项不加句号；说明和错误句用句号。省略号使用单字符 `…`。不要使用 em dash。
