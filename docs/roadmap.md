# 重建路线图

路线图按证据和风险推进。阶段完成需要满足退出条件，不以“代码已写”作为唯一标准。

## P0 证据基线

目标：建立不会混淆观察、静态线索和执行结果的产品事实库。

- 固化应用版本、系统版本、界面截图、Accessibility 树和安装包静态证据。
- 为现有能力分配稳定 `F-xxx` 编号。
- 为关键用户流程编写可重复 `V-xxx` 用例。
- 记录所有未知项，避免在实现中隐式决定产品行为。

退出条件：`docs/features.md` 可追溯到证据，`docs/verification.md` 覆盖高风险功能，文档检查通过。

## P1 原应用行为验证

目标：把关键能力从 `L1` 或 `L2` 提升到 `L3`。

- 在隔离临时目录验证 Finder 菜单展示、上下文匹配和单项操作。
- 优先验证新建、复制移动、打开工具、常用目录和永久删除保护。
- 验证 17 个工具箱命令的输入范围、结果、错误与清理行为。
- 查找二维码和翻译入口，不能定位时保留为静态线索。
- 用新用户或隔离偏好域验证首次启动值，避免修改现有配置。

退出条件：核心流程已有可重复证据，未知行为不再阻塞最小产品范围定义。

## P2 技术可行性 PoC

目标：验证最难逆转、最影响架构的系统约束。

- 使用独立 bundle ID 建立 SwiftUI/AppKit 主程序和最小 Finder Sync Extension。
- 验证扩展启用流程、Finder 菜单更新延迟、权限和系统版本差异。
- 对主程序与扩展通信做最小 PoC，再选择共享容器、偏好或其他机制。
- 把可共享的菜单规则和文件操作规划为无界面的纯逻辑，保持扩展轻量。
- 确认签名、entitlement、沙盒和候选发布渠道的约束。

候选架构不是最终决定。通信 PoC、签名、新 bundle ID 和发布渠道均为开放问题。

退出条件：关键系统能力在目标 macOS 版本运行，架构选择有可重复证据支撑。

## P3 核心闭环

目标：实现可以日常使用的最小 RightKit 重建版本。

- 完成设置持久化、扩展状态和基础菜单构建。
- 实现已通过 `L3` 验证的核心功能，不用推测填补原应用未知行为。
- 为用户可见流程建立 E2E 验证和结果产物。
- 明确迁移策略，但不直接读取或覆盖旧应用配置。

退出条件：核心 `F-xxx` 项达到验收标准，隔离安装不会影响原 RightKit。

## P4 完整能力与兼容

目标：按证据逐步覆盖工具箱、上下文匹配和高级能力。

- 逐项实现并验证工具箱命令。
- 完成图片转换、图标集、文件夹图标等复杂流程。
- 根据验证结果决定二维码和翻译是否进入范围。
- 覆盖多选、冲突、权限、符号链接、大文件和失败恢复场景。

退出条件：支持矩阵、限制和差异均有文档与测试依据。

## P5 发布准备

目标：形成可签名、可升级、可回滚的发行版本。

- 确定 bundle ID、签名、entitlement、隐私说明和发布渠道。
- 验证干净安装、升级、卸载、扩展启用和配置保留。
- 在支持的 macOS 版本执行发布回归。
- 记录与参考版本的已知差异。

退出条件：发布检查全部通过，原应用和用户数据仍保持独立。
