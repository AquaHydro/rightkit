# 实现顺序

每一段做完都应该能编译，并且该段对应的验收可以运行。不要等全部完成才补菜单测试。

## 1. 骨架和设置

建立主程序、访达扩展和 `RightKitCore`，同时落地 App Group entitlement、XPC 服务名和统一验证入口。落地设置模型和默认值，覆盖 `V-002`。

完成：全新启动的设置与功能规格的默认表一致，重启后修改还在。

## 2. 菜单和通信

先实现监视目录，再按菜单表生成扩展菜单，并用 XPC 把点击交给主程序。先做一条只读命令：拷贝路径。覆盖 `V-003`、`V-040` 和 `V-050`。

完成：监视目录内的空白处和各类选择的菜单与规格一致；工具栏始终只显示设置。扩展菜单回调里没有文件读取。

## 3. 文件主路径

实现新建、自定义模板、在应用中打开、两套目录、复制、移动、剪切和粘贴。覆盖 `V-010`、`V-020`、`V-030`。

完成：重名不覆盖，两套目录互不影响，终端和编辑器收到的目标不同。

## 4. 工具箱和删除

实现其余文件工具、哈希窗口和永久删除保护。覆盖 `V-041` 至 `V-044`，并确认 `V-045` 的已废弃命令没有进入菜单。

完成：哈希向量通过。受保护路径不会被删除。

## 5. 图片、服务和快捷指令

实现图片转换、两种图标集、壁纸、文件夹图标、二维码、翻译和 9 个 App Intents。覆盖 `V-046`、`V-060`、`V-061`、`V-074`。

完成：输出尺寸和文件位置与规格一致。彻底删除和解散文件夹不能从快捷指令调用。

## 6. 界面收尾

补上欢迎窗口、菜单栏、扩展状态、中英文案，并按设计规范检查浅色、深色和增强对比度。覆盖 `V-001`。

完成：设置窗口、哈希窗口和欢迎窗口都用系统组件；菜单栏不是弹出面板。
