# Finder 右键可见延迟：图标位图与启动预热

日期：2026-10-03。范围：`F-008`、`F-033`、`F-060`、`F-061`，验收 `V-051`。只改扩展的菜单呈现，不改菜单内容和命令。

## 发现

原有 `menu-performance` 日志只统计扩展内构建，首次约 25 ms、后续 5–15 ms，看不出问题。本次直接测量访达里从按下右键到菜单窗口出现的时间：在 RightKit 监视目录里约 410 ms，在不受监视的目录里约 136 ms，RightKit 让每次右键多出约 270 ms。

系统日志显示，扩展返回菜单之后，系统为了把菜单跨进程交给访达，会为每个应用和文件图标生成全部尺寸（单次右键 169 次图标生成请求，约 200 ms），然后访达才显示菜单。原实现只把多尺寸的 `NSWorkspace` 图标改了显示尺寸，没有去掉大尺寸版本。这段时间不在扩展计时之内。

## 实现

- `MenuRenderer` 把应用、文件类型和真实文件图标都画成只含一张 16 pt、2x 位图的图像，与 SF Symbol 的处理方式一致。`appAndFileIconsAreSingleSmallBitmaps` 在旧实现上失败，在新实现上通过。
- 扩展启动或设置变化后约 0.5 秒，用独立的呈现器在主线程按当前设置搭一遍文件菜单和空白处菜单并丢弃，提前连接图标服务。不共享菜单回调的缓存，不读取用户文件，日志记录 `prewarm_ms`。

## 测量方法

环境：Apple Silicon、macOS 27.0、Xcode 27.0，官网渠道 Debug 构建，三个版本使用相同配置：A 为 `origin/main`，C 只改图标，B 为图标加预热。每个版本单独注册为访达唯一的 RightKit 扩展，监视目录为主目录，在测试目录中选中一个文本文件，列表视图。

每轮先结束扩展并重启访达，打开窗口并等待 3 秒，再连续右键 5 次。[rclick.swift](2026-10-03-menu-icons/rclick.swift) 发送真实的右键事件，并轮询访达的弹出菜单窗口（窗口层级 101）出现的时间；[bench.sh](2026-10-03-menu-icons/bench.sh) 负责切换版本和重启。每个版本 3 轮，原始数据见 [finder-visible-ms.txt](2026-10-03-menu-icons/finder-visible-ms.txt)，扩展阶段日志见 [menu-performance.log](2026-10-03-menu-icons/menu-performance.log)。

## 结果

| 版本 | 重启访达后第一次右键（ms） | 之后的右键（ms） | 扩展内首次构建（ms） |
| --- | --- | --- | --- |
| A 原实现 | 646 / 456 / 451 | 376–425 | 23–24 |
| C 只改图标 | 187 / 188 / 199 | 125–140 | 26–28 |
| B 图标加预热 | 184 / 162 / 154 | 119–137 | 15–18 |
| 参照：不受监视的目录 | | 136–139 | |

改图标后，后续右键与不受监视的目录相同，RightKit 带来的额外可见延迟基本消失。预热让扩展内首次构建减少约 9 ms，第一次右键的中位数从 188 ms 降到 162 ms。样本只有 3 轮，这部分差距只能说明方向，不作为精确收益。预热本身在后台耗时 20–70 ms。

## 视觉检查

在真实访达中截图：[在应用中打开](2026-10-03-menu-icons/open-in-apps-light.png) 的应用图标、[复制到](2026-10-03-menu-icons/copy-to-light.png) 的文件夹图标和[工具箱](2026-10-03-menu-icons/toolbox-light.png) 的符号清晰且颜色正确；[深色模式](2026-10-03-menu-icons/copy-to-dark.png) 下的文件夹图标正常，深色下右键仍为 140 ms。

## 限制与清理

- 只测了本地目录与选中单个文件。外接盘、云盘、文件选择面板中的扩展实例和空白处右键没有单独计时。
- Debug 构建，未测 Release 和商店签名版本；可见时间包含轮询间隔（1 ms）和访达自身绘制。
- 测试前记录了原状态：只有 `/Applications/RightKit.app` 的商店版扩展启用，官网渠道未注册，系统为浅色。测试中临时关闭了商店版扩展，并在测试后恢复。三个测试副本放在 `/private/tmp`，没有替换已安装的应用，也没有读写商店版的设置。测试过程关闭了访达窗口并多次重启访达，深色模式检查后已切回浅色。测试目录已删除。
