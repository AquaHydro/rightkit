# 设置分栏切换性能，2026-10-12

## 结论与实现

切换时重复销毁和构建整页表单是这组负载的主要成本。设置页改为首次访问才创建真实 `NSHostingView`，后续回访复用控件。非当前页面从原生视图树移除，窗口关闭或语言变化时释放缓存；外部目录与应用状态在回访时刷新。没有预建五页，没有把文件访问授权结论作为 UI 缓存。

## 环境和方法

- macOS 27.0.1，基线提交 `0470610c17b73cec2067a6e24cb27555e4692e88`；优化版是本记录对应工作树，源码 SHA-256 见保存的构建清单。
- 两个独立 Release / `swiftc -O` 的商店条件测试程序，使用生产 `SettingsView`、真实 SwiftUI `Window`、分段工具栏及私有 suite 的 `AppStorage`。设置和待粘贴存储为内存替身，不启动生产 AppDelegate、Finder 扩展、agent 或更新检查。
- 相同实际内容尺寸 640 × 620 pt，3 个监视目录、6 个常用目录、6 个发送到目录，全部是测试创建的本地临时目录并带真实 bookmark；3 个应用、默认 12 个新建类型和工具箱。
- 全部编译结束后串行运行；按通用、新建文件、打开方式、目录、工具箱顺序切换，记录首轮及每页后续 20 次的中位数。初始通用页已经选中，不把它的无操作计为首次切换。
- 从 AppStorage 赋值计时，到主队列提交选中分栏后完成同步布局、绘制及 Core Animation 提交为止。等待和保存位图不计入样本。没有测鼠标输入到屏幕扫描呈现的完整延迟，也不是纯 CPU 时间。

首次访问仍需创建控件。下列每页仅一个样本，不能宣称为可靠的冷启动提升；此次改动主要解决反复切换。

`time -l` 记录的进程峰值 RSS 为 184.20 → 194.00 MiB，增加约 9.80 MiB。它包含框架、资源和位图采集，不是设置缓存的精确分配量。窗口关闭后释放所有页面的行为由弱引用测试验证。没有用一次性预建全部页面来换取热切换数据。

## 复现与证据

```sh
python3 scripts/perf/run_settings.py --baseline 0470610 --rounds 20
python3 scripts/perf/run_settings.py --no-build --interactive --variant working
```

首条会先完成两个版本的构建，再顺序采样，生成 `.build/settings-performance/` 下的 JSON、日志和内容位图。脚本检查构建清单，源码或探针改变后拒绝复用过期二进制；失败断言返回非零。交互预览只操作临时数据，请用菜单 Quit 结束并清理测试偏好。

仓库只保存[汇总数据](evidence/2026-10-12-settings-tabs/summary.json)、构建清单和运行日志。逐次原始样本和内容位图不入库，用上面的命令重新生成。内容位图不包含系统工具栏的完整合成，不作为屏幕呈现时间或完整窗口截图。

本次没有安装或替换 `/Applications/RightKit.app`，没有访问已安装应用的设置或改动系统扩展开关。同步目录查询仍受本地文件系统与 bookmark 状态影响，不把这些数值外推为离线卷或网络盘性能保证。
