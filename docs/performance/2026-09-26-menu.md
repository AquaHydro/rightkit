# Finder 菜单性能优化验证

日期：2026-09-26。范围：`F-008`、`F-033`、`F-060`、`F-061`，专项真机验收为 `V-051`。本次只优化右键菜单路径，不包含批量文件操作、二维码或图片引擎。

## 实现

- 一次菜单规则构建只整理一次监视目录，每个选择路径只整理一次；其他授权路径仍走原有逻辑。
- 同次构建复用发送目标的存在性与显示名，下一次构建重新查询。
- 同次呈现复用彩色图标，系统浅深色改变时清空符号位图缓存；每个菜单项取得独立 NSImage 副本，避免修改系统或缓存对象。
- 待粘贴文件未变时只查询版本，不重复读取和解码；只有可能显示粘贴的上下文才查询。工具栏完全跳过文件上下文。
- 根据开启的命令读取隐藏标记和扩展名显示状态；选择元数据不跨菜单缓存。
- `menu-performance` 记录初始化和菜单阶段计时，区分扩展实例首个菜单回调。总计时不含日志输出或 Finder 绘制。

## 测量方法

环境：Apple Silicon arm64、macOS 27.0（26A428）、Apple Swift 6.4。核心使用 `swift build -c release`，驱动和呈现器使用 `swiftc -O`。优化前代码来自 `2b86f8d00132276196197f97f2d4da6be0519cfb` 的同版核心及原始 `makeItem`/`menuSymbol` 实现，提取为独立驱动；优化后使用扩展实际引用的 `MenuRenderer` 和 `PendingPasteState`。两边使用相同机器、编译模式和负载。

完整构建负载：30 个真实临时目标目录，10000 条待粘贴记录，0/1/100/1000 个真实临时文本文件。每次重新读取文件元数据、生成规则和构建 NSMenu/NSMenuItem，包含图标查询与符号位图绘制。应用列表为空，每组 50 次。规则规模测试每组 20 次，选择项都匹配最后一个监视目录，无发送目标。原始数据：[优化前](2026-09-26-menu/before.txt)、[优化后](2026-09-26-menu/after.txt)。

| 负载 | 优化前 p50 / p95（ms） | 优化后 p50 / p95（ms） |
| --- | --- | --- |
| 完整构建，空白处 | 7.287 / 7.599 | 2.020 / 2.194 |
| 完整构建，1 个文件 | 10.273 / 10.518 | 2.062 / 2.121 |
| 完整构建，100 个文件 | 11.421 / 11.608 | 3.038 / 3.150 |
| 完整构建，1000 个文件 | 21.582 / 22.315 | 11.529 / 11.795 |
| 规则，30 个监视目录、1000 项 | 45.654 / 47.480 | 2.713 / 2.760 |
| 规则，30 个监视目录、10000 项 | 457.100 / 467.772 | 27.061 / 27.511 |
| 读取未改变的10000条待粘贴状态 | 5.081 / 5.273 | 0.001 / 0.004 |
| 暖缓存菜单呈现，1000项上下文 | 2.976 / 3.038 | 0.830 / 0.853 |

完整构建的空白处首样本为优化前 42.969 ms、优化后 41.068 ms。首次图形资源加载没有显示出明确改善，不能用暖缓存收益宣称“首次右键瞬开”。待粘贴状态首读仍需约 5 ms；列表变化后也会重读。

执行 `python3 scripts/perf/run_menu.py` 可复测当前实现。它只创建并清理自己的临时文件，不启动或注册 RightKit，不读写用户设置。统计包括首样本；p95 使用 nearest-rank。呈现器 cold 指缓存为空，不代表整个扩展进程冷启动。

## 2026-09-27：隔离菜单交互重试与清理

使用同一 `MenuRenderer` 的临时 AppKit 窗口，通过 UI 工具实际点击。测试回调只显示命令和 tag，不执行文件操作。

- 浅色：打开菜单、展开工具箱、点击「拷贝路径」，界面反馈 `已收到：copyPath，tag=3`。
- 深色：切换外观、打开菜单、展开工具箱、点击「拷贝名称」，界面反馈 `已收到：copyName，tag=4`，截图确认窗口切换成深色。
- 切回浅色：菜单重新打开，辅助功能树包含剪切、复制到、移动到和工具箱。
- 弹出菜单会在跨调用焦点变化后关闭，因此连续动作在每步读取新辅助功能树后执行。窗口截图只包含主窗口，不能据此宣称弹出层图标和高亮已经截图验收。
- 测试结束后结束精确匹配的 MenuPreview 进程，注销 LaunchServices 中的测试包，删除 `.build/perf-audit/MenuPreview.app` 和临时驱动源文件，检查同标识偏好和窗口恢复目录。确认无 MenuPreview 进程或测试包残留，Spotlight 查询测试标识也没有结果。

此补测消除了隔离菜单展开和点击的阻塞；`V-051` 的真实 Finder 验收仍保持 Planned。
